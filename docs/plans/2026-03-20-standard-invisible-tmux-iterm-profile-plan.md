# Invisible tmux via iTerm Profile

## Problem

The user wants headless operation (sessions survive reboots, work without GUI) but direct tmux interaction broke their workflow. The current iTerm/AppleScript setup is simple but fragile — requires a logged-in GUI session and iTerm running.

## Goals

1. Identical daily UX to current iTerm workflow (open tab, run claude, see in app)
2. Sessions survive iTerm crashes and Mac Mini reboots
3. Works headless when user is away
4. One-time setup, zero ongoing tmux interaction
5. No breaking changes for Linux tmux users

## Solution

Create an iTerm Dynamic Profile called "Claude Remote" that runs `tmux -CC new-session -A -s claude` as its shell command. When set as default, every new iTerm tab is silently a tmux window. Server uses the tmux adapter via `CLAUDE_REMOTE_ADAPTER=tmux`. User never types `tmux`.

`-A` flag: attach to existing `claude` session or create it. `-CC`: iTerm control mode — tmux windows render as native tabs.

## Technical Approach

### Adapter Selection (No Platform Lie)

Introduce `CLAUDE_REMOTE_ADAPTER=tmux` env var — separate from platform detection. This selects the tmux adapter on any OS without pretending macOS is Linux.

Update `detect.js`:
```javascript
// New: explicit adapter override (works on any OS, no platform lie)
const adapterOverride = process.env.CLAUDE_REMOTE_ADAPTER;
if (adapterOverride === 'tmux') {
  cachedAdapter = require('./linux-tmux');
  return cachedAdapter;
}
// Existing: CLAUDE_REMOTE_PLATFORM override (backwards-compatible for Linux users)
// Existing: auto-detect via os.platform()
```

`CLAUDE_REMOTE_PLATFORM=linux` continues to work unchanged for Linux users. The new `CLAUDE_REMOTE_ADAPTER=tmux` is the recommended way on macOS.

### macOS Compatibility Audit of linux-tmux.js

The `linux-tmux.js` adapter uses:
- `tmux list-panes` — works on macOS
- `tmux send-keys` via `execFile` — works on macOS
- `tmux capture-pane` — works on macOS
- No Linux-specific paths or APIs

**Confirmed compatible.** No separate `macos-tmux.js` needed. Document this in the adapter file header.

### tmux Session Name — Single Source of Truth

The session name `claude` must be consistent between the iTerm profile and server discovery. Define it as a constant:

- **Server:** reads `TMUX_SESSION_NAME` from `.env` (defaults to `claude`)
- **iTerm profile:** setup script generates the profile JSON using the same value
- **Never hardcoded independently** in two places

### iTerm Dynamic Profile

Drop JSON in `~/Library/Application Support/iTerm2/DynamicProfiles/`:

```json
{
  "Profiles": [{
    "Name": "Claude Remote",
    "Guid": "claude-remote-tmux-profile",
    "Command": "/opt/homebrew/bin/tmux -CC new-session -A -s claude",
    "Custom Command": "Yes"
  }]
}
```

Session name in the command is generated by the setup script from the config source of truth.

### Setup Script — Idempotent, Per-Step

`scripts/setup-iterm-tmux.sh` runs as a sequence of idempotent steps:

1. **Check prerequisites:**
   - tmux installed (abort if not)
   - iTerm2 installed and version >= 3.0 (warn if not)
   - Auto-login status check (warn if disabled, explain trade-off)

2. **Install Dynamic Profile:**
   - Generate JSON with session name from config
   - Write to DynamicProfiles dir
   - Set file immutable: `chflags uchg profile.json`
   - Verify file exists and matches expected content

3. **Update `.env`:**
   - Safe key-value update: check if key exists → update; doesn't exist → append
   - Never overwrite the full file
   - Add `CLAUDE_REMOTE_ADAPTER=tmux`
   - Verify `AUTH_TOKEN` still present after modification
   - Enforce `chmod 600 .env`

4. **Create LaunchAgent:**
   - Write plist to `~/Library/LaunchAgents/`
   - Set read-only: `chmod 444`
   - `KeepAlive: true` for restart-on-failure
   - `StandardOutPath` and `StandardErrorPath` to `~/Library/Logs/ClaudeRemote/`
   - Create log dir with `chmod 700`

5. **Print summary:**
   - Per-step success/failure status
   - Instructions: set "Claude Remote" as default iTerm profile
   - Instructions: add iTerm to Login Items
   - Warning about auto-login + physical security trade-off
   - Warning about non-iTerm terminals being invisible

Each step checks preconditions and reports clearly. Safe to re-run.

### Server Boot — `run-server.sh`

```bash
#!/bin/bash
cd "$(dirname "$0")"
export PATH="/opt/homebrew/bin:/usr/local/bin:/usr/bin:/bin:$PATH"
export HOME="/Users/dazz"

# Enforce .env permissions
if [ "$(stat -f '%A' .env 2>/dev/null)" != "600" ]; then
  echo "ERROR: .env permissions too permissive (must be 600)" >&2
  exit 1
fi

set -a; source .env; set +a

# Wait for tmux (max 30s, then fail)
for i in $(seq 1 30); do
  /opt/homebrew/bin/tmux list-sessions >/dev/null 2>&1 && break
  [ "$i" -eq 30 ] && { echo "ERROR: tmux not available after 30s" >&2; exit 1; }
  sleep 1
done

exec /opt/homebrew/bin/node server.js
```

- Never uses `set -x` (prevents token leakage to logs)
- 30s timeout on tmux wait with explicit error
- LaunchAgent's `KeepAlive: true` restarts on failure
- Permissions check on `.env` before sourcing

### Server Network Binding

Confirm `server.js` binds to `127.0.0.1` only (localhost). cloudflared tunnel handles external access. Document this in setup output.

### Error Recovery Flows

**Server unreachable (app side):**
- iOS/web: existing "Disconnected" banner with reconnect attempts
- No new app code needed — existing reconnection logic handles this

**tmux crashes while away:**
- Server's liveness check detects sessions gone → broadcasts `session_ended`
- When iTerm restarts (or user reopens), `tmux -CC new-session -A -s claude` recreates the session
- User must restart Claude manually in the new session (from app or keyboard)

**iTerm doesn't start after reboot:**
- Server starts via LaunchAgent (independent of iTerm)
- Server runs but discovers no sessions (tmux has no panes)
- App shows empty session list: "No active sessions" (existing empty state)
- User can SSH in: `open -a iTerm` to start iTerm remotely

**LaunchAgent fails:**
- `KeepAlive: true` restarts automatically
- Logs in `~/Library/Logs/ClaudeRemote/` for debugging
- App shows "Disconnected" until server recovers

### Log Management

- `StandardOutPath`: `~/Library/Logs/ClaudeRemote/server.log`
- `StandardErrorPath`: `~/Library/Logs/ClaudeRemote/server.err`
- Log dir created by setup script with `chmod 700`
- Add to macOS `newsyslog.conf` for rotation (or document manual cleanup)

## Acceptance Criteria

### Core UX
- [ ] After setup, new iTerm tabs are tmux windows (user doesn't type tmux)
- [ ] Running `claude` in a tab → appears in app (web and iOS)
- [ ] Closing iTerm → sessions survive → reopening restores all tabs
- [ ] After reboot (with auto-login): iTerm → tmux → server → app works

### Setup
- [ ] Setup script is idempotent (safe to re-run)
- [ ] Setup detects and warns if auto-login is disabled
- [ ] Setup checks iTerm2 version >= 3.0
- [ ] `.env` permissions enforced as 600
- [ ] LaunchAgent plist set read-only (444)
- [ ] Existing `.env` values not overwritten on re-run

### Adapter
- [ ] `CLAUDE_REMOTE_ADAPTER=tmux` selects tmux adapter on macOS
- [ ] `CLAUDE_REMOTE_PLATFORM=linux` still works for Linux users (no regression)
- [ ] tmux session name configurable from single source of truth

### Error Recovery
- [ ] Server starts independently of iTerm (LaunchAgent)
- [ ] `KeepAlive` restarts server on crash
- [ ] `run-server.sh` fails with clear error if tmux not available in 30s
- [ ] `run-server.sh` aborts if `.env` permissions are too permissive
- [ ] App shows "Disconnected" when server unreachable, reconnects automatically

### Security
- [ ] Server binds to localhost only (`127.0.0.1`)
- [ ] Logs written to `~/Library/Logs/ClaudeRemote/` with `chmod 700`
- [ ] No `set -x` in any script that sources `.env`

## Risks

| Risk | Mitigation |
|------|------------|
| iTerm doesn't auto-start on login | Setup adds to Login Items; documented |
| Auto-login is physical security risk | Documented trade-off; recommend FileVault |
| Auto-login disabled (FileVault, MDM) | Setup detects and warns; document manual start fallback |
| Non-iTerm terminals invisible | Documented in setup output + CLAUDE.md |
| tmux crashes while away | Server detects via liveness; iTerm recreates session on reopen |
| Profile JSON tampering | Set immutable after install (`chflags uchg`) |
| `.env` too permissive | Permission check in `run-server.sh`; enforced in setup |
| Log growth | Specify log paths with rotation guidance |

## Test Strategy

### Happy Path
1. Run setup script → verify per-step output
2. Re-run setup script → verify idempotent (no duplicates, no overwrites)
3. Open new iTerm tab → verify it's a tmux window (`tmux list-sessions`)
4. Open tab without typing `tmux` → verify the AC "user never types tmux"
5. Run claude → verify appears in app (web and iOS)
6. Close iTerm → verify `tmux list-sessions` still shows sessions
7. Reopen iTerm → verify tabs restored
8. Reboot Mac Mini → verify full recovery chain

### Failure Injection
9. Kill tmux server → verify server detects session loss, app shows disconnect
10. Stop LaunchAgent → verify `KeepAlive` restarts it
11. Set `.env` to 644 → verify `run-server.sh` aborts with error
12. Disable auto-login → reboot → verify server starts (LaunchAgent) but no sessions (no iTerm)
13. Open Terminal.app → run claude → verify it does NOT appear in app (expected: invisible)
